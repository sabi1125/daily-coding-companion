# Claude Code rules for this project

## Reply length

Default explanation shape is three short lines, no more:

- **What:** the problem, one line.
- **Why:** one sentence, only if non-obvious.
- **Fix:** the actual code/command.

No history lessons, no narrated testing, no migration speculation, no headers/bold
section breaks for a single fix. If the user asks "why" or "explain more," then expand —
don't pre-empt it.
