# API Docs

## Google sign in API
### `GET /auth/google`

**Summary**
Starts google sign in and redirects to google's consent screen.

**Description**
Sets authorization url to Location header and sends back `302 Found` status code.

1. API is called.
2. Create authorization url.
    - client_id: Project's unique apps.googleusercontent.com string.
    - redirect_uri: Where to redirect the user after consent.
    - response_type: Set to code if you are using the standard authorization code flow.
    - scope: A space-separated list of permissions or APIs your app wants to access.
    - state: A random, unique string generated by your app to prevent Cross-Site Request Forgery (CSRF) attacks.
3. Set generated random state in cookies temporarily.
4. Sets authorization url in the Location header.
5. Returns with status code `302 Found`

**Auth** — None

**Header**
Location: google authorization url.

**Responses**
`302 Found`

**Errors**

| Status | Category | When | Body |
|---|---|---|---|
| 500 | Unexpected | On processing failure | `{ "message" : "internal server error" }` |

## Google callback API
### `GET /auth/google/callback`

**Summary**
Signs in user via google Oauth.

**Description**

If the user is signing in for the first time create's the user's record in the `users` table and signs user in . Else validates the user and signs in. 
Redirects to the login screen if not a valid user.

1. Google calls with `code` and `state` query params.
2. Check if the `state` matches with the `state` set in `Google sign in API`.
    - If `state` does not match exit with `401 Unauthorized`.
    - If the `state` does match carry on to the next process.
3. Exchange `code` for the following using `Google Client Secret`.
    - access_token: Temporary key to call Google APIs (expires in 1 hour).
    - refresh_token: Long-term key used to get new access tokens automatically.
    - id_token: Secure identity profile (user ID, name, email, avatar).
    - expires_in: Lifetime of the access token in seconds (usually 3600).
    - token_type: Type of token, which is always "Bearer".
    - scope: List of permissions the user actually granted.
        - If google api's cannot be accessed exit with `503 Service Unavailable`.
        - If google accessed but return's error exit with `502 Bad Gateway`.
        - If invalid `code` exit with `400 Bad Request`.
4. Verify `id_token` and get `user_id` stored in `id_token`.
    - If not valid exit with `401 Unauthorized`.
5. If user does not exist in the `users` table create user else move to next step.
    - If user creation fails exit with `500 Internal server error`.
6. Upsert `oauth_credentials` with `refresh_token`.
    - If upsert fails exit with `500 Internal server error`.
7. Insert record in `sessions` table and set cookie with `sessions.session_id`.
    - If insert fails exit with `500 Internal server error`.
8. Redirect user to `Today` page.

**Auth** - None

**Cookie** - session.session_id

**Query parameters**

| Name | Type | Required | Description |
|---|---|---|---|
| code | string | YES | Code set by google which is used to exchange for user creds |
| state | string | YES | CSRF token set by Google sign in API |


**Responses**
`302 Found`

**Errors**

| Status | Category | When | Body |
|---|---|---|---|
| 400 | Expected |  On bad request | `{ "message" : "Bad Request" }` |
| 401 | Expected |  On invalid access   | `{ "message" : "Unauthorized" }` |
| 500 | Unexpected | On processing failure | `{ "message" : "internal server error" }` |
| 502 | Operational | On errors returned by google | `{ "message" : "Bad gateway" }` |
| 503 | Operational | On connection failure to google | `{ "message" : "Service Unavailable" }` |

## Get Today's problem API

### `GET /problems/today`

**Summary**
Get's the problem that was generated for that day.

**Description**
Get's the problem that was generated that day in the following format.

1. Checks current date's problem exists in `problems`.
2. If problem exists, return it with `200 Success`.
    - If get from database fails exit with `500 Internal Server Error`.
3. If problem does not exist, check whether a record with `retried = true` already exists for today.
4. If exists, the retry already happened and failed — return `404 Not Found`.
5. If no `retried = true` record exists yet, invoke ingest now, writing the new `ingest_runs` record with `retried = true`.
    - If the email fetch itself fails (Gmail unreachable, no email found, parse error) exit with `404 Not Found`.
    - If the fetch succeeds but writing the new `problems`/`ingest_runs` records fails (a DB write failure), exit with `500 Internal Server Error`.
    - If the fetch succeeds and the write succeeds, return the new problem with `200 Success`.

**Auth** — Required

**Cookie** - session.session_id

**Responses**

`200 Success` — problem exists (step 2), or the retry in step 5 just succeeded.

      "raw_problem": "Given an array of integers nums and an integer target, return indices of the two numbers such that they add up to target.",

| Status | Category | When | Body |
|---|---|---|---|
| 404 | Expected | Retry already used up (either it was already used before this call, or the email fetch just failed during this retry) | `{ "message" : "no problem available today" }` |
